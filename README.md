# HEC Pyrochlore Oxide Property Predictor

Machine-learning pipeline for predicting **lattice parameter** and **thermal conductivity**
of high-entropy pyrochlore oxides (A₂B₂O₇) from composition alone.

## Data

The project keeps two clearly separated data tiers. **`data/raw/` is read-only input** —
these files are exactly as pulled from their sources and are never written to by any
script. **`data/processed/` is 100% derived output** — every file there is generated by
code in `src/data/` and `src/features/`, can be safely deleted, and will be rebuilt
automatically the next time a `get_*_dataset()` function or `models/*.py` script needs it.

If you are adding new experimental or literature data, it almost always belongs in
`data/raw/` (see [Adding New Data](#adding-new-data) below) — you should rarely need to
hand-edit anything in `data/processed/`.

### `data/raw/` — source files (one per data provenance)

| File | Rows/format | What it is | Loaded by |
|---|---|---|---|
| `Sample_Properties_Safin_Feb_2026.csv` | lab measurements | In-house experimental HEC pyrochlore samples: sintered compositions, TPS thermal-conductivity measurements, relative density, synthesis method, and refined lattice parameters from XRD. This is the group's own primary data. | `src/data/make_combined_dataset.py::load_safin` |
| `HECPyrochlore_latt_data_ICSD.csv` | ICSD export | Bulk export from the Inorganic Crystal Structure Database (ICSD) of all known pyrochlore-prototype entries (`StructureType` = Ca₂Nb₂O₇ / Eu₂Zr₂O₇ / Bi₂Ti₂O₇), including single-element ("pristine") and doped/mixed ("high-entropy") compositions, cell parameters, and literature DOIs. | `src/data/load_icsd.py` (via `make_combined_dataset.py::load_icsd_source`) |
| `aflow_pyrochlore_data_comb.csv` | AFLOW export | DFT-computed pyrochlore entries pulled from the AFLOW materials database: composition, relaxed lattice parameter, elastic moduli, band gap, thermal conductivity/expansion (AGL model), density, and energetics. Used only for **pristine** (single A, single B) compounds. | `src/data/load_aflow.py` |
| `mp_pyrochlore_query.csv` | Materials Project export | DFT-computed pyrochlore entries queried from the Materials Project API: lattice constants, density, band structure, formation energy, energy above hull, and (where available) bulk/shear modulus. Also pristine-only. | `src/data/load_mp.py` |
| `notebookLM_dataset.csv` | small curated table | Hand-curated structural parameters (oxygen positional parameter *x*, anion vacancy δ, B–O distance/angle, conductivity type) for a handful of reference pyrochlores and non-pyrochlore pyrochlore-adjacent oxides, extracted from literature via NotebookLM. Mainly used for structural sanity checks rather than model training. | `src/data/make_combined_dataset.py::load_nlm` |
| `parent_components.csv` | family-level summary | One row per *parent compound family* (e.g. "Lanthanide Zirconates", "Seven-Element Zirconate") giving typical A-/B-site cation sets, average thermal conductivity, and qualitative key properties. This is reference/context data, not per-composition training data. | `src/data/make_combined_dataset.py::load_parent_components` |
| `Jordan_pyrochlore_data.csv` | literature CTE table | Thermal-expansion coefficient (CTE) values for pyrochlores and related oxides (garnets, silicates, etc.) pulled from a wide literature survey, with source DOI per row. Currently used for thermal-expansion context rather than the lattice/conductivity models directly. | `src/data/make_combined_dataset.py::load_jordan_source` |

**None of the files above are ever modified in place.** Adding a new source means adding a
new file here plus a small loader function that maps it onto the canonical schema (see
`src/globals.py::CANONICAL_COLS`).

### `data/processed/` — generated/derived files

Everything in this folder is produced by running the data pipeline (`src/data/make_combined_dataset.py`,
`src/data/load_data.py`, and `src/features/rule_of_mixture_cal.py`). They exist purely as
build artifacts/caches so repeated training runs don't have to re-parse every raw source
every time. **If a processed file looks stale or wrong, delete it — the next `get_*_dataset()`
call will regenerate it from `data/raw/`.**

| File | Built by | Contents |
|---|---|---|
| `combined_pyrochlore.csv` | `make_combined_dataset.py::build_combined_dataset()` | The unified, canonical-schema table combining **all** raw sources (Safin, ICSD, notebookLM, parent components), classified per row as `pristine` / `high_entropy` / `non_pyrochlore` (non-pyrochlore rows are dropped). This is the master table both the lattice and thermal models are ultimately built from. |
| `pristine_pyrochlore.csv` | `make_combined_dataset.py::build_single_phase_dataset()` | Subset of the combined data restricted to **single-element A-site, single-element B-site** ("pristine") pyrochlores only, pooled from ICSD + AFLOW + Materials Project and de-duplicated by (Sample A, Sample B). Includes DFT-derived mechanical/thermal properties (bulk/shear/Young's modulus, Poisson ratio, thermal expansion) where available. This is the **lookup table (`PYROCHLORE_DB`)** used by the Rule-of-Mixtures calculator (`src/features/rule_of_mixture_cal.py`) to interpolate properties for high-entropy compositions from their pristine endpoints. |
| `hec_pyrochlore.csv` | `make_combined_dataset.py::build_high_entropy_dataset()` | Subset of the combined data restricted to **high-entropy** (≥2 elements on either site) pyrochlores, from Safin + notebookLM + ICSD, with per-row `a_stoich_json` / `b_stoich_json` mole-fraction dictionaries (so non-equiatomic compositions like Gd₁.₉Ce₀.₁Ti₂O₇ are preserved exactly, not approximated as equiatomic). This is the target-composition set that gets ROM-enriched and used to train the lattice model. |
| `rom_hec_latt.csv` | `src/data/load_data.py::get_lattice_rom_dataset()` (calls `rule_of_mixture_cal.py::rom_from_dataframe`) | `hec_pyrochlore.csv` enriched with Rule-of-Mixtures (ROM) predicted properties — `ROM_Lattice_Parameter`, `ROM_Ionic_Radius_A/B`, `ROM_Electronegativity_A/B`, `ROM_Bulk/Shear/Youngs_Modulus`, `ROM_Poisson_Ratio`, `ROM_Pyrochlore_Stable`, etc. — computed by weighting each composition's pristine A₂B₂O₇ endpoints (looked up in `pristine_pyrochlore.csv`) by their mole fractions. Rows missing a required pristine endpoint get `NaN` ROM columns and are excluded from training. This is the file actually fed into `models/validate_rom_latt.py`. |
| `engineered_pyrochlore_latt.csv` | `src/data/load_data.py::get_lattice_dataset()` | `combined_pyrochlore.csv` after `build_features.add_engineered_features()` (compositional entropy, radius statistics, electronegativity contrast, etc.) and NaN-column cleanup, restricted to rows with a known lattice parameter. Feeds the "compositional-features-only" lattice model in `models/predict_rom_latt.py` / `models/validate_lattice.py`. |
| `engineered_pyrochlore_therm.csv` | `src/data/load_data.py::get_thermal_dataset()` | Same feature-engineering step as above but for the thermal-conductivity target (`TPS Cond W/m/K`), including `lattice_parameter` as an extra input feature. Feeds `models/predict_thermal.py` / `models/validate_thermal.py`. |

**Rule of thumb:** raw → *what actually happened in a lab or database*; processed →
*what the feature-engineering and rule-of-mixtures code computed from that raw data*.
If you need to trace a number back to its source, start in `data/raw/`; if you're
debugging a model input, start in `data/processed/`.

## Quick Start

Run all scripts from the **project root** (`HECPyrochlore/`).

### Predict Lattice Parameter

**Interactive mode** (prompts for A-site and B-site elements):
```bash
python models/predict_lattice.py
```

**CLI mode** (single prediction):
```bash
python models/predict_lattice.py --a "Pr,Sm,Gd,Ho,Lu" --b "Ti"
python models/predict_lattice.py --a "La,Gd,Lu" --b "Ti,Zr"
```

**Force re-train** before predicting:
```bash
python models/predict_lattice.py --train --a "Sm,Eu,Gd,Tb,Dy" --b "Ti"
```

### Predict Thermal Conductivity

**Interactive mode:**
```bash
python models/predict_thermal.py
```

**CLI mode** (lattice parameter is optional — auto-predicted if omitted):
```bash
python models/predict_thermal.py --a "Sm,Eu,Gd,Tb,Dy" --b "Ti" --lattice 10.185
python models/predict_thermal.py --a "La,Gd,Lu" --b "Ti,Zr"   # auto lattice
```

### Validate Models (Full Report + Plots)

```bash
python models/validate_lattice.py
python models/validate_thermal.py

# Custom number of CV folds:
python models/validate_lattice.py --splits 10
python models/validate_thermal.py --splits 5
```

Each validation script prints:
- Cross-validation R², RMSE, MAE for all 4 models
- Hold-out test-set metrics for the best model
- Top-15 features ranked by **permutation importance** and tree MDI
- Feature-group analysis (A-site vs. B-site vs. cross-site)
- Saves 3 plots + a full text report to `models/<task>/`

## Supported Elements

**A-site** (8-coordination, rare-earth cations):
`La Ce Pr Nd Sm Eu Gd Tb Dy Ho Er Tm Yb Lu Y`

**B-site** (6-coordination, transition metals):
`Ti Zr Hf Sn Ir Ce Nb`

Compositions are assumed **equiatomic** unless otherwise noted (non-equiatomic ICSD
entries carry exact mole fractions in `a_stoich_json` / `b_stoich_json`; see
[Data](#data) above).

## Feature Engineering

All features are derived purely from elemental properties — no DFT required.

| Feature Group | Examples | Physical Meaning |
|---|---|---|
| A-site | `a_site_entropy`, `a_site_mean_radius`, `a_site_delta` | Cation size disorder, configurational entropy |
| B-site | `b_site_entropy`, `b_site_mean_radius`, `b_site_delta` | Octahedral-site chemistry |
| Cross-site | `a_b_radius_ratio`, `total_entropy`, `phonon_scattering_factor` | Pyrochlore stability, phonon scattering |
| Lattice-derived | `lattice_parameter`, `lattice_volume`, `density_theoretical` | Used for thermal model only |

Key feature definitions:
- **δ (delta)** = `sqrt(Σ xᵢ(1 - rᵢ/r̄)²)` — lattice distortion index
- **S_config** = `-R Σ xᵢ ln(xᵢ)` — configurational entropy (J/mol·K)
- **phonon_scattering_factor** = `S_config × δ_total` — composite phonon scattering proxy
- **r_A/r_B** = A-site to B-site mean ionic radius ratio (governs pyrochlore stability)

## Models

Four regressors are compared in cross-validation; the best is automatically selected:

| Model | Notes |
|---|---|
| **GradientBoosting** | Usually best; balanced bias-variance |
| **RandomForest** | Robust; good uncertainty via tree variance |
| **ExtraTrees** | Faster; slightly higher variance |
| **Ridge** | Linear baseline; useful for interpretability |

## Key Findings (Feature Importance)

**Lattice Parameter** — dominated by **B-site properties**:
1. `b_site_mean_molar_mass` — heavier B-site → larger unit cell
2. `b_site_n_elements` — B-site complexity drives distortion
3. `b_site_mean_radius` — direct structural effect

**Thermal Conductivity** — dominated by **cross-site and A-site disorder**:
1. `a_b_radius_ratio` — size mismatch drives phonon scattering
2. `a_site_delta` — A-site lattice distortion index
3. `b_site_en_mean` — B-site electronegativity (bond stiffness)
4. `phonon_scattering_factor` — composite entropy × disorder metric

## Adding New Data

New data always goes in **`data/raw/`**, never `data/processed/`.

1. Drop your CSV into `data/raw/` with columns matching (or mappable to) the canonical
   schema in `src/globals.py::CANONICAL_COLS` (`Sample A`, `Sample B`, `Lattice Parameter
   (Angstrom)`, `Thermal Conductivity (W/m/K)`, etc.).
2. Write a small loader function in `src/data/make_combined_dataset.py` (or a dedicated
   `src/data/load_<source>.py` module, following the pattern of `load_icsd.py` /
   `load_aflow.py` / `load_mp.py`) that reads the raw file and returns a DataFrame in the
   canonical schema.
3. Register the loader in `build_combined_dataset()` (and `build_single_phase_dataset()` /
   `build_high_entropy_dataset()` if it contains pristine or high-entropy compositions).
4. Delete the stale files in `data/processed/` (or just re-run the pipeline — it detects
   missing files and rebuilds automatically):

```python
from src.data.load_data import get_lattice_dataset
X, y, names = get_lattice_dataset()   # rebuilds data/processed/*.csv as needed
```

Force re-train with the `--train` flag on any predict script after adding data.
